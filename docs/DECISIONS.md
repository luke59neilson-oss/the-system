# Decisions log

Newest at the bottom. Format: ID · date · decision · why.

- D1 · 2026-10-21 · TypeScript monorepo with npm workspaces: `packages/engine` (pure rules), `apps/server` (Fastify + ws), `apps/web` (React + Vite), `apps/desktop` (Electron + electron-builder). · One language end to end; players need only a browser; the GM gets a double-click app.
- D2 · 2026-10-21 · Persistence is an append-only JSONL event log plus snapshots; no native database modules. · Gives the audit log, undo, and session reports for free, and avoids Electron native-module rebuilds.
- D3 · 2026-10-21 · Players join by picking their character, no password (Luke's call). GM commands only from loopback or with a GM key generated at launch. · Keeps it simple at the table while stopping a player's browser from running GM actions.
- D4 · 2026-10-21 · Default port 30333. · Avoids Foundry VTT's 30000 in case it runs on the same machine.
- D5 · 2026-10-21 · Players see their own sheet in full; the party view shows name, race/class, levels and pool bars only. · Luke's default answer; keeps per-player surprises intact.
- D6 · 2026-10-21 · XP is a number per event; default split even across chosen participants, adjustable. XP per level by grade: G 100, F 150, E 250, D 400, C 650, B 1,000, A 1,500. · Luke wants numeric XP; the curve keeps numbers growing with grade. Configurable.
- D7 · 2026-10-21 · One configurable currency, default name "Credits". · Luke wants money transfers; name to be confirmed.
- D8 · 2026-10-21 · CI runs tests on push (ubuntu only). Windows/macOS/Linux desktop builds run only on push to the `release` branch. · Private-repo Actions minutes are limited and Windows/macOS minutes count extra.
- D9 · 2026-10-21 · No Claude API calls inside the app. The app exports session reports (and can optionally sync them to a GitHub repo); Claude-drafted content comes back as importable JSON. · Luke wants to carry notes to Claude and bring ideas back; no API key or cost in the app.
- D10 · 2026-10-21 · Adversarial review: Sonnet reviews each item, Fable reviews each milestone, always a fresh context. · Luke asked for reviews by different models.
- D11 · 2026-10-21 · Build installers for Windows, macOS and Linux. · Luke's laptop OS is not confirmed yet.
- D12 · 2026-10-21 · Free points are assigned once and then locked; the GM can override. · Luke's rule.
- D13 · 2026-10-21 · Grade themes are metallic: aluminum (dull), bronze (dull), copper, silver, gold, platinum (cool tint to separate it from silver), prismatic diamond. · Luke's choice; platinum tint added because silver and platinum look alike on screens.
- D14 · 2026-10-21 · Roadmap revised after a Sonnet review: per-item e2e specs, milestone acceptance items, engine reordering, capped review rounds with model fallback, 90-minute lock with 35/60-minute timebox, GM key always required, canary leak tests, event versioning with a golden log. · Review findings, all High items adopted.
- D15 · 2026-10-21 · Releases come from a workflow on push to the `release` branch, which creates the GitHub Release itself. · Build sessions cannot push tags, delete branches, or write via the GitHub API (verified).
- D16 · 2026-10-21 · Free points lock per level-up batch, not once per character. · "Assign once" read literally would block every later level-up.
- D17 · 2026-10-21 · Added milestone MS (walking skeleton + perspective switcher + demo campaign + preview desktop build) right after the core engine and server items, and a preview release after every later milestone. · Luke wants to run the app early and watch GM changes land on player screens.
- D18 · 2026-10-21 · TypeScript pinned to 6.0.x, not 7.x. · typescript-eslint 8.72 supports TS < 6.1; TS 7 (native port) would break type-aware linting.
- D19 · 2026-10-21 · The server serves the app shell only for GET/HEAD browser navigations (Accept: text/html) outside `/api`, `/health`, `/ws`. · Keeps missing assets and server routes as real 404s while allowing dotted client routes.
- D20 · 2026-10-21 · Banned patterns are enforced twice: ESLint rules (incl. engine purity: no host globals, clock, RNG, dynamic or non-relative imports except zod) and a repo-wide regex scanner in `npm run check`. · Inline lint-disable comments can't be reported by ESLint alone; two layers make accidental bypass unlikely.
- D21 · 2026-10-21 · `campaign.levelCap` must equal some grade's top level; grades above the cap may be defined ahead of time and are unreachable. · Keeps every reachable grade complete and lets S-grade be added by appending a grade and raising the cap.
- D22 · 2026-10-21 · Rules-config edit events (M4.9) will address array entries (grades, pools, stats, rarities, slots) by id, never by index. · An append-only log must survive inserts and reorders.
- D23 · 2026-10-21 · The rules config is strict: unknown keys are errors, so adding a setting means bumping `configVersion` and adding a migration that fills the default. · Prevents GM edits on mistyped or stale keys from being silently dropped.
- D24 · 2026-10-21 · World Stability starts at 100 (range 0–100), hidden from players by default. · DESIGN gives the range and toggle but no starting value; a dying world counts down.
- D25 · 2026-10-21 · Character state stores the grade by id, carries a `schemaVersion`, and is plain readonly data; pools are whole numbers (floored), current pools clamp to 0..max. · Survives grade inserts and replays cleanly under event sourcing (M1.3).
- D26 · 2026-10-21 · Starting class skills must be at or below the first grade's rarity ceiling and unique by name (case-insensitive, including Identify). · DESIGN §3 gives G-grade a Rare ceiling; duplicate names would make skill references ambiguous.
- D27 · 2026-10-21 · Undo is an `event.undone` event naming its target; state is the fold of every event not undone ("as if it never happened"). Undoing an undo and undoing `campaign.created` are rejected; to redo, the GM re-issues the command. · One rule covers every event type, including non-latest undo, without hand-written inverses that could drift from the reducer.
- D28 · 2026-10-21 · Replay checks undo targets against the log, then folds the events that still count once (O(n)). It accepts the same final states as incremental appends but does not re-check each undo's intermediate fold. · Keeps 50,000-event loads fast (M11.3); logs are only written through `appendEvent`, which does the full check.
- D29 · 2026-10-21 · Golden logs (`packages/engine/test/golden/*.jsonl` + `.state.json`) are frozen; payload changes need a `schemaVersion` bump and an upcaster, and a coverage test lists event types no golden log contains yet (only `character.professionGranted`, unreachable until M1.10). · Proves old campaign logs keep loading.
- D30 · 2026-10-21 · Character create events store the creation input, not the resulting character; the reducer re-derives it with the rules in the log. · Smaller events; the golden test catches any drift in creation rules.
